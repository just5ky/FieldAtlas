# CrowdStrike Identity Protection: SsoUserLogonFailure

**Vendor:** CrowdStrike Identity Protection (Next-Gen SIEM)
**Sigma category:** crowdstrike.ssouserloginfailure
**Event ID:** SsoUserLogonFailure

An initial, failed sign-in attempt to an SSO facilitator: an IDaaS
directory (Azure AD, Okta), a federation portal (ADFS, Ping Federate), or a
combination of both. Generated by CrowdStrike Identity Protection for the
Public Cloud platform. Fields below are raw sensor field names; CrowdStrike
Sigma rules match on these directly, so the native and Sigma name columns
are identical.

## Detection notes

`SourceAccountUserName` with repeated failures across many distinct
`SourceEndpointAddressIP4` values in a short window is credential
stuffing; the same username with many failures from one IP is a targeted
brute force. `SourceEndpointIpReputation`/`SourceEndpointIpRiskScore` flags
(proxy/VPN/datacenter/known-malicious) on the source IP turn either pattern
into a high-confidence alert even at low failure counts. `AzureErrorCode`/
`OktaErrorCode` distinguish bad-password failures (worth aggregating,
expected background noise) from MFA-challenge and conditional-access
failures, worth alerting on individually since they indicate a valid
password was used. `LocationCountryCode` inconsistent with a user's normal
geography, combined with `ClientUserAgentString` showing scripting/headless
tooling instead of a normal browser, is a strong automated-attack signal.

## Volume notes

Volume scales with org size and password hygiene. Expect background noise
from normal mistyped-password failures, spiking sharply during active
credential-stuffing campaigns. Baseline per-user failure rate before
alerting on raw failure counts; the reputation/risk-score fields are the
higher-signal filter for prioritization.
